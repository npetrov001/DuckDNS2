# DuckDNS2

Windows-service based rewrite of the DuckDNS updater (.NET Framework 4.8, one EXE).
Generated by Claude with specific instructions to make it a single EXE which combines Management UI, Service, and Tray Icon mode.

## Modes of `DuckDNS2.exe`

| Command | What it does |
|---|---|
| `DuckDNS2.exe` | **Manager** (asks for admin): Install / Uninstall / Start / Stop Service, edit configuration (domain, token, interval, advanced multi-domain), live status of the last update, Update Now, open log. |
| `DuckDNS2.exe -start` | **Tray icon** (no admin): yellow = last update OK, blue = updating, red = failed / service not running / not configured. Double-click = status window. Menu: Update Now!, Status, Open Manager, Start with Windows, Exit. |
| *(started by Windows)* | **Service** `DuckDNS2` (LocalSystem, delayed auto start, auto-restart on crash) that performs the updates. |
| `-install`, `-uninstall`, `-startservice`, `-stopservice` | Silent service control for scripts (exit code 0 = OK). |
| `-debug` | Runs the service engine inside the process (service must be stopped). |

## How the pieces talk

The service hosts a named pipe `\.\pipe\DuckDNS2.Service` (any authenticated local user may connect).
Commands: `STATUS` (last result, time, messages, next update), `UPDATE` (push an update now), `RELOAD` (re-read config + update).
Messages are length-prefixed JSON (`Ipc\IpcMessages.cs`).

## Files

* Config: `%ProgramData%\DuckDNS2\DuckDNS.cfg` - same format as the original `DuckDNS.cfg` (can be imported from the Manager; a `DuckDNS.cfg` next to the EXE is picked up automatically on first run).
* Log: `%ProgramData%\DuckDNS2\DuckDNS2.log`
* The folder is restricted to SYSTEM + Administrators (it contains the token).

## Behaviour

* First update 10 s after service start, then every *interval*; after a failure it retries after 5 minutes (if the interval is longer).
* Copy the EXE to its final location **before** clicking *Install Service* - the service points at the EXE you install it from.
